## Workstream A: Fix DAG rendering (issues 12a, 12b, 12c)

These are bugs in how `generate_userstory_artifacts.py` + `generate_site.py`
render highlighted/isolated DAG views and how `userstory_dag_data.yaml` defines
story paths.

### A.1 — Audit and fix US-1a.1 path in YAML

**Problem:** US-1a.1 ("Single bank + CSV") is highlighted on node `cfg_1b1w`
("1 bank + 1 wallet") when it should only touch `cfg_1b` ("1 bank account").

**Root cause:** Check the `paths` field for US-1a.1 in the YAML. Currently
`paths: [[cfg_1b]]` — this is correct. So the rendering bug is either:

1. The site page for US-1a.1 is picking up the wrong story's paths, OR
1. The highlighted DAG view is colouring `cfg_1b1w` because other stories share
   the same overlay and the highlight logic is broken.

**Action:**

1. Read `generate_site.py` function `generate_story_html()` — verify that the
   SVG highlight attributes (`data-node`) are populated from the correct story's
   `paths`, not from all stories.
1. Read the JavaScript in the generated HTML — verify that on page load only
   the nodes from `NODE_PATH` are highlighted, not the full SVG.
1. If the overlay/full-DAG SVG is used, verify `add_data_attributes_to_svg()`
   correctly tags only the target story's nodes.
1. Fix whichever component is wrong.

**Files:**

- `user_stories/dag/generate_site.py`
- `user_stories/dag/userstory_dag_data.yaml` (if path is wrong)

### A.2 — Suppress arrows to unvisited nodes in per-story views

**Problem:** In the per-story DAG (both the site page and the isolated `.puml`
files), edges are drawn to nodes that the story does not visit.

**Root cause:** Two possible sources:

1. `generate_dot_full()` in `generate_userstory_artifacts.py` — when
   `only_story_id` is set it already restricts `visible_nodes` and
   `visible_edges` to the target story. Bug may be in the site's SVG variant
   (which is generated by `generate_site.py`'s `generate_svg()`).
1. The site may be using the full-overlay SVG instead of the per-story isolated
   SVG.

**Action:**

1. In `generate_site.py`, check which SVG is embedded in each story page.
1. If it is the overlay SVG, change it to use the per-story isolated SVG (or
   generate a per-story SVG inline).
1. If JavaScript is responsible for hiding/showing edges, verify that edges not
   in `NODE_PATH` are hidden.

**Files:**

- `user_stories/dag/generate_site.py`

### A.3 — Verify edge correctness for each demo story

**Problem:** Even after A.1 and A.2, specific stories may have wrong edges if
their `paths` in the YAML are incorrect.

**Action:**

1. For each story with `data_use: demo` or `data_use: both`, verify that the
   `paths` list matches the intended data flow from the user story description.
1. Cross-check against the `demo_paths` and `component_filter` fields.
1. Fix any mismatches.

**Files:**

- `user_stories/dag/userstory_dag_data.yaml`

## Workstream B: Split configuration layer into sublevels (issue 13)

This is the largest structural change. Currently each config node
(e.g. `cfg_1b1w`) bundles account_configs, dir_paths, file_names,
categorisation, and matching_algo as flat `components`. The request is to
make these separate sublayers in the DAG.

### B.1 — Design the sublevel node structure

**New layers** to insert between the current `config` layer position and the
`categories` layer:

```
config_accounts      (sublevel 13.a)
config_dir_paths     (sublevel 13.b)
config_file_names    (sublevel 13.c)
config_categorisation (sublevel 13.d)
config_matching_algo  (sublevel 13.e)
```

Each sublevel gets its own nodes. For example, `config_accounts` would have:

- `acct_triodos_csv` — "Triodos checking (EUR CSV)"
- `acct_eur_wallet` — "EUR physical wallet"
- `acct_ing_csv` — "ING checking (EUR CSV)"
- `acct_gbp_wallet` — "GBP physical wallet"
- `acct_btc_wallet` — "BTC digital wallet"
- `acct_gold_wallet` — "GOLD physical wallet"
- `acct_silver_wallet` — "SILVER physical wallet"
- etc.

For `config_dir_paths`, `config_file_names`, `config_categorisation`, and
`config_matching_algo`, create one node per unique configuration variant
referenced by the existing config nodes.

**Action:**

1. Enumerate all unique component IDs across all `config` nodes in the YAML.
1. Create a mapping from old `cfg_*` nodes to the set of new sublevel nodes.
1. Define the new layer entries and nodes in a design document.

### B.2 — Update `userstory_dag_data.yaml`

**Action:**

1. Add the 5 new sublayers to the `layers:` section, between `config` and
   `categories`.
1. Create nodes in each sublayer for each unique component.
1. Remove the `config` layer entirely (or keep it as a top-level entry point
   with a single "Configuration" label node if desired).
1. Update every story's `paths` to route through the relevant sublevel nodes
   instead of `cfg_*`. For example, US-1a.1 currently has
   `paths: [[cfg_1b]]`. It would become:
   ```yaml
   paths:
     - [acct_triodos_csv, dir_default, files_default, catcfg_default, matchalgo_default]
   ```
   Or, if the sublevel nodes are still prefixed by the parent config variant:
   ```yaml
   paths:
     - [acct_triodos_csv, dirp_1b, fnames_1b, catcfg_1b, malgo_1b]
   ```
1. Update `demo_paths` and `component_filter` accordingly (component_filter may
   become unnecessary since each sublevel node is now its own entity).
1. Update `gif_video` references if the video stem naming changes.

**Files:**

- `user_stories/dag/userstory_dag_data.yaml`

### B.3 — Update `generate_userstory_artifacts.py`

**Action:**

1. Add the new layer names to `LAYER_ORDER`, `LAYER_COLOURS`, and
   `node_shape()`.
1. The rest of the rendering logic (`generate_dot_full()`,
   `generate_cli_view()`, etc.) should work automatically since it is
   data-driven from the YAML. Verify by regenerating all artifacts.

**Files:**

- `user_stories/dag/generate_userstory_artifacts.py`

### B.4 — Update `generate_site.py` and `story_components.py`

**Action:**

1. Update `story_components.py` `get_marker_sequence()` — the component
   interleaving logic may need adjustment since components are now top-level
   nodes.
1. Update `generate_site.py` if it has hardcoded layer references.
1. Update `SECTION_TO_GIF_DIR` if new sections are introduced.

**Files:**

- `user_stories/dag/story_components.py`
- `user_stories/dag/generate_site.py`

### B.5 — Update GIF marker emissions

**Action:**

1. Update `@@NODE` markers in `.cast` files / `generate.sh` scripts to emit

1. Update `_markers.json` sidecar files accordingly.
1. Re-record config GIFs if the TUI flow changes.

**Files:**

### B.6 — Update navigation buttons (issue 13.e)

## Workstream C: Fix receipt labelling issues (14a, 14b)

### C.1 — Show receipt image alongside labelling TUI (issue 14a)

**Problem:** The receipt labelling page/GIF does not show the receipt image on
the side.

**Action:**

1. In the story site HTML (`generate_site.py`), for stories in
   "Step 2b: Receipt Labelling", add the receipt image alongside the video.
   The image path can be derived from the story's `paths` — extract the
   `receipt_img` layer node, look up its `label` (which is the filename), and
   reference it from the site's `assets/` directory.
1. Alternatively, add a `receipt_image` field to the YAML story definition and
   render it in the site template.
1. For the GIF itself, this would require the TUI to display the image in a
   side panel. Check if the TUI (`edit_receipt_tui.py`) supports image display
   or if this needs to be added.

**Files:**

- `user_stories/dag/generate_site.py`
- `user_stories/dag/userstory_dag_data.yaml` (optional: add `receipt_image` field)
- `src/hledger_preprocessor/editing/edit_receipt_tui.py` (if TUI change needed)

### C.2 — Fix receipt labelling timestep flow (issue 14b)

**Problem:** The US-2b.2 GIF navigates through every configuration, category,
matching, and starting journal node before reaching the actual receipt labelling
nodes. It should only navigate through the receipt label fields.

**Root cause:** The story's `paths` include the full end-to-end path
(config → journal). The `demo_paths` field should specify just the receipt
labelling segment, but US-2b.2 currently has no `demo_paths` field.

**Action:**

1. Add a `demo_paths` field to US-2b.2 that starts at the receipt image and
   goes through only the receipt label nodes:
   ```yaml
   demo_paths:
     - [img_coffee_cash, lbl_coffee_cash]
   ```
1. Do the same for other Step 2b stories (US-2b.3, US-2b.4, US-2b.5) that
   lack focused `demo_paths`.
1. In the site generation, ensure that the `--demo-paths` flag (or the site
   generation logic) uses `demo_paths` when available for video timestamp
   synchronisation.
1. In `generate_site.py`, verify that `get_marker_sequence()` uses
   `demo_paths` when building the navigation chips for the story page.

**Files:**

- `user_stories/dag/userstory_dag_data.yaml`
- `user_stories/dag/generate_site.py`
- `user_stories/dag/story_components.py`

**Problem:** `DonutAI()` fails with `No module named transformers`.

**Action:**

at the point where auto-linking occurs.

1. Re-record the matching demo to capture the marker in the `.cast` file.

## Workstream F: Synchronise navigation buttons with DAG nodes (high-level issues)

### F.1 — Ensure nav buttons = DAG nodes

**Problem:** The navigation buttons (breadcrumb chips) and the DAG nodes are
not the same set.

**Root cause:** Navigation chips are built from `get_marker_sequence()` which
interleaves parent nodes and sub-components. DAG nodes are the top-level node
IDs. After Workstream B (splitting config into sublevels), the sub-components
will become top-level nodes, which should align the two.

**Action:**

1. After completing Workstream B, verify that the chip labels match the DAG
   node labels.
1. If there are still mismatches (e.g. some chips exist that have no DAG node,
   or vice versa), fix `get_marker_sequence()` to produce exactly the set of
   DAG nodes in the story's `paths`.
1. Ensure clicking a chip seeks the video to the correct timestamp AND
   highlights the corresponding DAG node.

**Files:**

- `user_stories/dag/story_components.py`
- `user_stories/dag/generate_site.py`

### F.2 — Fix GIF-to-button mapping

**Problem:** The wrong navigation buttons are linked to the wrong GIFs.

**Action:**

1. After completing Workstreams A–E, regenerate the site.
1. For each story page, verify:
   - The video shown is the one specified by `gif_video`.
   - The chips/buttons match the nodes in the story's `paths` (or `demo_paths`).
   - Clicking a chip seeks to the correct video timestamp.
1. Fix any remaining mismatches in the YAML or site generation code.

### F.3 — Generate GIFs from YAML-declared paths

**Problem:** GIFs are created manually and don't follow the YAML path order.

**Action:**

1. Review each demo script in `gifs/automation/real_*.py`.
1. Ensure each script:
   - Loads the story's marker sequence from the YAML
     (via `StoryMarkerEmitter`).
   - Emits `@@NODE` markers in YAML-declared order.
   - Visits nodes in the order specified by the story's `demo_paths`.
1. Where a demo script does not use `StoryMarkerEmitter`, refactor it to do so.
1. Re-record all demos that were updated.

**Files:**

- `gifs/automation/real_*.py` (all demo scripts)
- `gifs/automation/core/screen.py` (verify `emit_node_marker` works)

## Workstream G: Dual-view per user story (solution from ui-issues_v2.md)

### G.1 — Add "full story" vs "segment only" view toggle

**Problem:** The user wants two view modes per story:

- **A. Full story:** From config all the way to journal output (with relevant
  sections boxed).
- **B. Segment only:** Just the bit of the story relevant to its section.

**Action:**

1. In `generate_site.py`, add a toggle button to each story page that switches
   between:
   - Full path view (using `paths` from YAML).
   - Segment view (using `demo_paths` from YAML, or the section-specific
     subset of `paths`).
1. When in full path view, render the full DAG with the story's path
   highlighted and add a visual box/border around the section-specific nodes.
1. When in segment view, render only the nodes from `demo_paths`.
1. Store the toggle state in localStorage so it persists across page loads.

**Files:**

- `user_stories/dag/generate_site.py`

### G.2 — Add section boxing to full-path DAG view

**Action:**

1. In `generate_dot_full()`, when rendering a highlighted story, add subgraph
   clusters around the nodes that belong to the story's primary section.
   Use a dashed border and section label.
1. This provides the "box around relevant sections" the user requested.

**Files:**

- `user_stories/dag/generate_userstory_artifacts.py`
